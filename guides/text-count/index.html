글자 수가 도구마다 다른 이유

공백, 줄바꿈, 이모지, 바이트를 구분해 제출 양식의 제한을 확인합니다.

작성: Toolhub 운영자 rayv · 업데이트 2026.10.24

먼저 제한의 단위를 확인하세요

자기소개서나 게시글 양식의 “500자”와 “1,000바이트”는 같은 제한이 아닙니다. 글자 수는 텍스트를 세는 규칙이고, 바이트 수는 저장 인코딩에 따라 결정됩니다. UTF-8에서 영어 알파벳 A는 1바이트, 한글 가는 3바이트지만 모든 문자에 한 가지 배수를 적용할 수는 없습니다.

“A가” → 2개 코드 포인트 · UTF-8 4바이트

이 예시는 따옴표를 제외한 문자열입니다. UTF-16을 쓰는 프로그램은 또 다른 길이를 표시할 수 있습니다.

눈에 보이는 한 글자가 여러 문자일 수 있습니다

일부 이모지는 피부색이나 결합 문자, 여러 사람 그림을 이어 붙여 만듭니다. 화면에는 하나의 아이콘으로 보이지만 내부적으로 여러 코드 포인트일 수 있습니다. 받침이나 악센트를 별도 문자로 표현하는 경우도 있습니다. 그래서 눈에 보이는 글자 수, 코드 포인트 수, JavaScript 문자열 길이가 항상 일치하지 않습니다.

공백 제외에도 규칙이 필요합니다

일반 띄어쓰기만 빼는지, 탭과 줄바꿈도 빼는지에 따라 결과가 달라집니다. 웹 양식에 붙여 넣을 때 줄바꿈이 바뀌거나 앞뒤 공백이 자동 제거되기도 합니다. 도구의 숫자를 제출 결과로 확정하지 말고, 실제 제출 화면의 카운터를 마지막 기준으로 삼으세요.

  1. 입력 규정에서 글자·바이트·공백 포함 여부를 확인합니다.
  2. 도구에서 여유를 두고 길이를 줄입니다. 이모지나 특수문자를 쓰면 더 주의합니다.
  3. 제출 양식에 붙여 넣어 표시되는 길이와 잘림 여부를 확인합니다.
  4. 제출하기 전 원문 사본을 따로 보관합니다.

민감한 글을 다룰 때

계산은 브라우저에서 실행되지만, 공용 기기에는 클립보드나 브라우저 기록이 남을 수 있습니다. 주민번호·계좌번호·지원자 개인정보가 들어간 원문은 불필요하게 공유하지 마세요. 이 가이드는 특정 채용 사이트의 글자 계산 방식을 보장하지 않습니다.
